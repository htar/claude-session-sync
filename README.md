# Session Sync for Claude Code

> Unofficial community extension. Not affiliated with or endorsed by Anthropic. «Claude» and «Claude Code» are trademarks of Anthropic.

Продовжуйте сесію Claude Code на іншому пристрої. Розширення переносить історію сесій
(`~/.claude/projects/<проєкт>/<id>.jsonl`) між вашими комп'ютерами. Свого сервера в нього немає: дані ходять
через те, чим ви вже користуєтесь.

**Три способи на вибір:**

- **GitHub:** вхід в один клік, приватний репозиторій створюється сам.
- **Хмарне сховище:** iCloud Drive, Dropbox, OneDrive, Google Drive, MEGA, pCloud, Box, Proton Drive, Nextcloud.
- **Власний git-репозиторій.**

**Що ще вміє:** показати список сесій зі сховища (назва, дата, розмір) і підтягнути лише вибрані; відкрити сесію
одним кліком (`claude --resume`); не перезаписувати сесію, яку продовжили на двох пристроях; пропускати завеликі й
старі сесії.

## Налаштування (один раз, 30 секунд)

Перший **Push** сам запитає, як сесії мають ходити між пристроями. Є три способи:

| Спосіб                      | Що треба                                                            | Як це працює                                                                                                                                                                                |
| --------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **GitHub (автоматично)**    | Акаунт GitHub                                                       | Входите через вбудований вхід VS Code, розширення саме створює **приватний** репозиторій `claude-sessions` у вашому акаунті. Якщо такий репозиторій уже є, але публічний, він відхиляється. |
| **Спільна папка**           | iCloud Drive, Dropbox, OneDrive або мережевий диск                  | Вибираєте папку в хмарі, розширення кладе туди сесії, а хмара доставляє їх на інші пристрої. Акаунтів і токенів не треба.                                                                   |
| **Власний git-репозиторій** | Приватний репозиторій і доступ до нього (SSH або credential helper) | Вказуєте `claudeSessionSync.repoUrl`. Розширення ніколи не питає пароль: інтерактивні запити git вимкнено.                                                                                  |

Змінити спосіб пізніше: **Claude Sync: Choose sync method**.

На другому пристрої встановіть розширення, виберіть той самий спосіб (для папки це та сама хмарна папка, для GitHub той самий акаунт) і зробіть **Pull**.

| Налаштування                          | За замовчуванням | Що робить                                                                                      |
| ------------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------- |
| `claudeSessionSync.mode`              | порожньо         | `github`, `folder` (хмарне сховище) або `git`. Порожньо = спитати при першому використанні.    |
| `claudeSessionSync.syncFolder`        | порожньо         | Спосіб «хмарне сховище»: папка із сесіями (заповнюється після вибору).                         |
| `claudeSessionSync.repoUrl`           | порожньо         | Спосіб «власний git»: адреса приватного репозиторію.                                           |
| `claudeSessionSync.claudeDir`         | `~/.claude`      | Папка конфігурації Claude.                                                                     |
| `claudeSessionSync.maxFileSizeMB`     | `90`             | Сесії більші за це **не пушаться** (і про них попереджають). GitHub відхиляє файли від 100 МБ. |
| `claudeSessionSync.maxSessionAgeDays` | `30`             | Пушаться лише сесії, змінені за останні N днів. `0` = без обмеження.                           |

Усі налаштування діють на рівні машини: задавайте їх у User settings, а не в налаштуваннях воркспейсу.

## Команди (палітра команд, префікс «Claude Sync»)

| Команда                | Що робить                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------- |
| **Push sessions**      | Копіює транскрипти поточного воркспейсу в сховище (репозиторій чи папку).           |
| **Choose sync method** | Змінити спосіб: GitHub, спільна папка чи власний git.                               |
| **Pull sessions**      | Забирає зміни зі сховища й кладе нові/довші транскрипти в локальну папку Claude.    |
| **Resume a session**   | Показує список сесій за першим запитом і відкриває термінал `claude --resume <id>`. |

Типовий сценарій: на ноутбуці **Push** → на робочому столі **Pull** → **Resume a session**.

## Як це працює

- **Ключ проєкту.** Шляхи на пристроях різні, тому сесії зберігаються за slug git-remote воркспейсу
  (`owner/repo`), а за його відсутності за назвою папки. Локально файли потрапляють у папку, яку Claude Code
  називає за шляхом воркспейсу.
- **Безпечне копіювання.** Транскрипт лише дописується, тому перезаписується лише коли довший файл починається
  з коротшого. Копіювання атомарне (тимчасовий файл + rename).
- **Конфлікти.** Якщо сесію продовжили на двох пристроях одночасно, жоден файл не перезаписується:
  розширення попереджає про конфлікт. Скопіюйте потрібну версію вручну.
- **Гонки.** Операції в межах одного вікна виконуються послідовно. Якщо інший пристрій встиг запушити раніше,
  push повторюється один раз після pull.
- **Ліміти push.** Один файл понад 100 МБ валить увесь push, тому більші за `maxFileSizeMB` сесії пропускаються з
  попередженням, а старші за `maxSessionAgeDays` просто не беруться (їх кількість показується в повідомленні).
  Старий файл не вважається «завеликим». Pull ліміти не застосовує. Порожні файли сесій (Claude інколи залишає
  такі) ігноруються: їх не синхронізують і не показують у списку.
- **Список для Resume.** Назва береться з першого тексту користувача (блоки контексту IDE пропускаються), порядок
  за часом останнього запису в сесії, бо mtime файлу після pull дорівнює часу pull. Читається лише початок і кінець
  файлу, а не весь транскрипт.

## Безпека і приватність

- **GitHub-спосіб** просить дозвіл `repo` (GitHub не має вужчого для приватних репозиторіїв). Токен лишається у VS Code і передається git через змінні оточення, а не через адресу чи командний рядок. Код відкритий, його можна перевірити.
- **Папка з iCloud:** якщо увімкнено «Optimize Mac Storage», macOS може не завантажити файл. Розширення покаже, скільки таких сесій, і підкаже, що зробити.

- Транскрипти містять ваш код, вивід команд і **можливо секрети**. Сховище має бути приватним (репозиторій або ваша хмарна папка).
  Перед першим push розширення показує попередження.
- Адреса репозиторію перевіряється: допускаються лише `https`, `ssh`, `user@host:path` і абсолютний шлях.
  Значення, що починаються з `-`, та транспорти на кшталт `ext::` відхиляються.
- `git` запускається без shell (`execFile`), з таймаутом.
- Розширення не працює в недовіреному (untrusted) воркспейсі.
- Файли з репозиторію приймаються лише за іменем сесії (`[0-9a-zA-Z-]+.jsonl`).

## Обмеження

- Синхронізуються сесії поточного воркспейсу (першої відкритої папки), а не всі проєкти одразу.
- Підпапки сесій (наприклад дані субагентів) не синхронізуються, лише основні `*.jsonl`.
- Синхронізація ручна; автоматичного фонового режиму немає.

## Розробка

```bash
npm install
npm run check      # typecheck + eslint + prettier + тести (включно з реальним git і двома «пристроями»)
npm run build      # dist/extension.js (esbuild)
npm run package    # .vsix
```

Запуск для налагодження: відкрийте папку в VS Code і натисніть **F5** (конфігурація «Run Extension»).
Логіка винесена в `src/core` без залежності від VS Code API й повністю покрита тестами;
`src/extension.ts` лише з'єднує її з командами та UI.
